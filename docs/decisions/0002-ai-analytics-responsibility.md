# ADR 0002: Snowflake 자연어 분석과 Bedrock 보고서의 역할 분리

- 상태: 승인
- 결정일: 2026-09-07

## 배경

PANDOK에는 검증된 Gold 집계를 영어 Markdown으로 변환하는 AWS Bedrock 보고서 기능이 있다. 이 기능은 미리 정한 Athena 쿼리를 실행한 뒤 결과를 요약하므로, 개발자가 새로운 질문을 할 때 SQL과 입력 계약을 변경해야 한다.

개발자가 원하는 핵심 사용 방식은 정기 보고서보다 다음과 같은 즉석 질문이다.

- 어떤 무기의 평균 킬 수가 가장 높은가?
- 어떤 무기가 가장 먼저 많이 선택되는가?
- 노출 대비 선택률이 가장 낮은 무기는 무엇인가?
- 특정 옵션을 선택한 Run과 선택하지 않은 Run의 킬 수와 생존시간 차이는 얼마인가?

Silver와 Gold는 이미 Snowflake에서 계산되며, Run·무기·옵션 지표와 아이템 기준정보가 존재한다. 따라서 자연어 질의를 별도의 AWS SQL 생성 계층으로 중복 구현하기보다 Snowflake의 Semantic View와 Cortex Agent를 분석 인터페이스로 사용하는 편이 기존 구조와 일치한다.

## 결정

Snowflake Cortex Agent를 PANDOK의 핵심 자연어 분석 인터페이스로 사용한다.

- Semantic View에서 Run, 무기, 옵션, 킬 수, 생존시간과 게임 버전의 의미와 관계를 정의한다.
- 검증된 대표 질문과 SQL을 등록해 동일한 질문에 일관된 계산 규칙을 적용한다.
- 자연어 질문은 읽기 전용 분석 역할로 검증된 Gold 및 범용 분석 View만 조회한다.
- 생성 SQL, 결과, 표본 수와 분석 상태를 함께 표시한다.
- `INSUFFICIENT_SAMPLE`은 신뢰 가능한 비교 결과로 표현하지 않는다.

AWS Bedrock 보고서는 삭제하지 않고 선택 기능으로 유지한다.

- 검증된 Gold 집계를 정기 서술형 보고서로 보관해야 할 때만 사용한다.
- Airflow 기본값은 `enable_bedrock_report=false`로 유지한다.
- 자동 DAG 실행에서 Bedrock을 호출하지 않는다.
- 보고서가 실제 운영 요구가 되었을 때만 입력 크기와 실행 주기를 다시 검토한다.

## 근거

- 자연어 질문에 따라 SQL을 생성하는 기능은 고정 보고서보다 개발자의 탐색 요구에 직접 대응한다.
- Snowflake 안에서 Gold 계산, 의미 정의, SQL 생성과 권한 관리를 연결할 수 있다.
- Bedrock으로 같은 기능을 구현하면 Schema 설명, SQL 안전성 검사, 실행, 오류 재시도와 지표 정의 관리를 별도로 만들어야 한다.
- 두 AI 기능을 매번 실행하지 않아 비용과 운영 복잡도를 줄인다.
- Bedrock 구현을 보존하므로 향후 정기 보고 요구가 생겨도 다시 처음부터 만들 필요가 없다.

## 결과

- Snowflake는 Gold 계산뿐 아니라 대화형 분석 계층을 담당한다.
- AWS는 수집, S3 Iceberg 저장과 Athena 교차 검증을 담당한다.
- 개발자의 일회성 탐색 질문은 Semantic View를 통해 처리한다.
- 반복 사용되고 계산 규칙이 확정된 지표만 공식 Gold로 승격한다.
- AI 사용 자체가 목적이 아니라 사용자 요구와 비용에 따라 서로 다른 역할을 부여한 구조가 된다.

## 후속 작업

1. PANDOK Semantic View를 구현한다.
2. 개발자 대표 질문과 검증 SQL을 등록한다.
3. 읽기 전용 Cortex 권한과 사용량 제한을 설정한다.
4. Streamlit에 자연어 질문, 생성 SQL, 결과와 표본 경고 화면을 추가한다.
5. 구현과 검증이 끝난 뒤 `architecture.md`, 운영 절차 및 최종 발표 문서에 실제 구현 상태와 결정 근거를 반영한다.
