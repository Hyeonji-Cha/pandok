# Telemetry Privacy Field Review

This document inventories the current executable telemetry contract and Bronze wrapper so the anonymous
schema can be designed without losing required Run analytics. Decisions are design proposals and do not
change the executable contract until the Privacy-by-Design review is approved.

## Decision meanings

- `KEEP`: the current analytical meaning is compatible with Run-only anonymous telemetry.
- `MODIFY`: retain the analytical purpose but restrict its value, lifetime, precision, or name.
- `REMOVE`: the field or event conflicts with the no-player-linkage objective or has no remaining purpose.

Every retained string must be generated by the game from an approved value set. Free-form text is not
permitted. Every retained identifier must be random, scoped no wider than one Run, and must never be mapped
to a player, account, installation, or device.

## Event-type review

| Event | Current use | Analysis purpose | Identification risk | Decision | Reason |
|---|---|---|---|---|---|
| `session_started` | Contract, fixtures, generator, sequence validation | Marks an application session after consent | Requires session-level linkage and has no Run metric | `REMOVE` | Consent remains a client control; AWS does not need an application-session event |
| `run_started` | Contract, fixtures, generator, sequence validation | Establishes one gameplay attempt and starting state | Low when linked only by a per-Run random ID | `KEEP` | Required for Run reconstruction |
| `upgrade_options_shown` | Contract, fixtures, generator, sequence validation | Records the options actually offered | A rare option sequence can single out a Run but not a player without external linkage | `KEEP` | Required to calculate offer-to-pick behavior and selection bias |
| `upgrade_selected` | Contract, fixtures, generator, sequence validation | Records the selected option | A rare choice sequence can single out a Run | `KEEP` | Required for upgrade pick-rate and survival analysis |
| `run_checkpoint` | Contract, fixtures, generator, sequence validation | Records cumulative Run state every 60 active seconds | Detailed progression can fingerprint a Run | `MODIFY` | Keep Run analysis but enforce fixed intervals, bounded fields, and no cross-Run linkage |
| `run_ended` | Contract, fixtures, generator, sequence validation | Records final Run state and termination reason | Detailed final combinations can fingerprint a Run | `KEEP` | Required for duration, survival, death, and completion metrics |

## Common event fields

| Field | Current use | Analysis purpose | Identification risk | Decision | Reason |
|---|---|---|---|---|---|
| `event_id` | Every event; retry deduplication and conflict detection | Distinguishes a logical event from a retry | Becomes persistent if derived from a player or reused | `MODIFY` | Keep a random event UUID, scoped to one event, with no external mapping |
| `event_name` | Every event; schema dispatch | Identifies the gameplay fact type | None when restricted to an enum | `KEEP` | Required to process the event |
| `event_time` | Every event; ordering, generator, sequence validator | Reconstructs order and late arrival | Precise wall-clock time can correlate gameplay with an identifiable activity | `MODIFY` | Replace client wall-clock time with Run-relative ordering and timing in the anonymous schema |
| `source_type` | Every event; production/test separation | Prevents test traffic from entering product metrics | Low; controlled batches can still be identifying if too specific | `KEEP` | Required data-quality boundary; do not encode person or location in the value |
| `anonymous_user_id` | Every event; generator and Run correlation | Links events and Runs to one consented player | Persistent cross-Run pseudonymous identifier | `REMOVE` | Conflicts directly with the requirement that AWS cannot link separate Runs |
| `session_id` | Every event; generator and application-session correlation | Links events within an application session | Can link multiple Runs from the same player | `REMOVE` | Run-level analysis does not require application-session identity |
| `run_id` | Every Run event; sequence validation and future Kinesis partitioning | Links events within exactly one Run | Identifying if reused or mapped outside the Run | `MODIFY` | Generate a new random UUID for every Run, never reuse it, and never create a mapping table |
| `game_version` | Every event | Compares metrics between released builds | Unique internal build strings or timestamps can identify a tiny test cohort | `MODIFY` | Permit only approved public/coarse build versions; reject timestamps, usernames, and machine-specific suffixes |
| `schema_version` | Every event | Selects the executable contract | None when restricted to a contract version | `KEEP` | Required for safe schema evolution |

## Findings that block schema implementation

1. The current contract requires `anonymous_user_id` and `session_id`, so it permits cross-Run linkage.
2. The current validator sorts and compares events using precise `event_time`; replacing it requires a new
   Run-relative ordering rule rather than deleting the field in isolation.
3. The current generator creates one anonymous user and session identity for the entire generated sequence.
4. The Bronze wrapper stores `received_at` with millisecond precision and recognizes `unity_client` as a
   production ingestion channel.
5. Several content identifiers use an open string pattern instead of an explicit game-content allow-list.
6. Detailed upgrade combinations can fingerprint a Run, but they remain analytically necessary and become
   unacceptable only if AWS can associate the Run with a person or another Run.

## Proposed anonymous-contract direction

- Remove `session_started`, `anonymous_user_id`, and `session_id` from AWS-bound telemetry.
- Keep one random, unmapped `run_id` per Run and one random, unmapped `event_id` per logical event.
- Replace client wall-clock `event_time` with Run-relative `event_sequence` and existing relative gameplay
  time fields.
- Restrict game-content strings to approved values and bound arrays and payload size.
- Rework production ingestion so only the authenticated Türkiye gateway can submit
  `CONSENTED_PROD_PLAY`.
- Keep precise operational time, if it remains necessary, outside product metrics with documented precision
  and retention.

These proposals require a separate schema-design review before the JSON Schema, validator, fixtures,
generator, ingestion code, or Terraform is changed.
